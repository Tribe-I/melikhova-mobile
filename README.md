# Чек-лист диджитал продакта (мобильное приложение)

Интерактивная самооценка DPO по требованиям модели Tiny Teams. Мобильная версия лендинга https://tribe-i.ru/melikhova/landing/ на React Native и Expo (TypeScript). Работает на Android и iPhone, без WebView.

Автор: Светлана Мелихова.

## Экраны

Два таба сверху: «Главная» и «О приложении».

- **Главная.** Содержание лендинга: шкала оценки, общий процент, радар по семи блокам, прогресс блоков, фильтр и кнопка сброса, 37 пунктов в семи блоках.
- **О приложении.** Название, одна фраза о проекте и короткий хеш коммита. Хеш берётся из переменной `EXPO_PUBLIC_COMMIT`, без неё показывается `dev`.

## Обещания

Каждое обещание проверяется автоматически или вручную на телефоне.

1. **Заголовок и автор.** На главном экране есть заголовок «Чек-лист диджитал продакта», а внизу жирным написано «Светлана Мелихова». На экране «О приложении» виден хеш коммита сборки.
2. **Пункты не пропадают.** Данные лежат в `src/data/checklist.json` и совпадают с лендингом: 7 блоков, 37 пунктов, идентификаторы блоков уникальны, одинаковых пунктов нет. Новые пункты добавляются только в конец блока.
3. **Формула.** «Да» даёт 1, «Частично» даёт 0,5, «Нет» даёт 0. Балл блока равен сумме баллов, делённой на число пунктов блока. Общий процент считается по всем пунктам. Формула лежит в `src/lib/score.ts`.
4. **Сброс и фильтр.** «Сбросить оценки» (с подтверждением) обнуляет все оценки, и после перезапуска приложения они не возвращаются. Фильтр содержит три варианта: «Все пункты», «Не выполнено» и «Без оценки».
5. **Данные остаются на телефоне.** Приложение не обращается к сети и ничего не отправляет. Оценки хранятся только на телефоне (AsyncStorage, ключ `dpo-checklist-v1`).

## Как запустить локально

Нужен Node.js 22.

```bash
npm install
npx expo start
```

В терминале появится QR-код. Установите на телефон приложение Expo Go (App Store или Google Play) и отсканируйте код: на Android из Expo Go, на iPhone камерой. Телефон и компьютер должны быть в одной сети. Если не соединяется, запустите `npx expo start --tunnel`.

Хеш коммита в локальном запуске показывает `dev`. Чтобы проверить подстановку: `EXPO_PUBLIC_COMMIT=abc1234 npx expo start`.

## Сборка Android (APK)

Сборку запускает GitHub Actions вручную: вкладка **Actions** → **Android build** → **Run workflow**. Автоматической сборки на каждое изменение `main` нет: бесплатных сборок Expo в месяц немного.

Что делает workflow: ставит зависимости, проверяет типы, передаёт в сборку короткий хеш коммита (переменная `EXPO_PUBLIC_COMMIT` в окружении `preview` Expo) и запускает облачную сборку APK по профилю `preview` из `eas.json`. Зелёный запуск означает, что APK готов: ссылка на страницу сборки и на файл APK есть в итоге запуска (Summary). Экран «О приложении» показывает хеш коммита этой сборки.

Секрет `EXPO_TOKEN` (токен доступа Expo) хранится только в Settings → Secrets and variables → Actions. В коде его значения нет.

Установка на Android: откройте на телефоне ссылку на страницу сборки из Expo (или отсканируйте QR-код), скачайте APK и установите. Телефон попросит разрешить установку из этого источника: разрешите только для этого раза.

## Библиотеки

Кроме Expo и React Native подключены две библиотеки, обе входят в Expo Go:

- `@react-native-async-storage/async-storage` хранит оценки на телефоне (обещание 4);
- `react-native-svg` рисует кольцо процента и радар.

## Как предложить изменение

Создайте ветку от свежей `main`, внесите правку, откройте pull request. Напрямую в `main` не коммитим. Секреты (токены, ключи, `.env`) в репозиторий не кладём.
